# Spread forecast backtest

Generated by `demos/backtest_spread.py` on 2026-11-12 07:25 UTC: inputs built with code version 5bef496, fire masks rebuilt and scored with cb082c5.

Inputs are built with `backend.spread_inputs.build_inputs` (the live code path) for past fire days,
the model is `backend.spread_model.predict` with threshold 0.621, and the label is MODIS Terra detections on day t+1 (FIRMS archive) rasterized on the
same tile grid. FIRMS points carry no cloud mask, so there are no uncertain (-1) pixels: any pixel
without a detection counts as no fire. This is stricter than the training labels, and Terra
sees each place only about twice a day, so absolute scores are not comparable with the test-split
numbers in data/training/spread_results.csv. Model and persistence are compared on the same tiles.

**Fire masks in this report:** detection footprints at scale 0.5 (backend.fire_points.footprint_mask, the default since cb082c5) for today's fire, persistence and the label. The centre-pixel version is in centre_pixel/report.md. Check: centre-pixel masks rebuilt from cached FIRMS points differ from the saved ones in 0 tile-variants.

## Reading the results (written by hand after the run)

- **Fairest test: footprint ×0.5 for today's fire, persistence and the label.** It is the closest of
  these definitions to the MOD14A1 masks the model was trained and tested on: on 19 dated training tiles
  it matched them with IoU 0.63, against 0.34 for centre pixels. It also uses the same definition on
  both sides, so persistence and the model are judged alike. Centre pixels on both sides is the
  second fair test.
- **The mixed definitions are not fair tests.**
  - Centre-pixel inputs with footprint labels give the only PASS. The cause is a mismatch, not a better
    model: persistence is handicapped by thin one-pixel fires against a wider label, while the model
    spreads fire outward anyway.
  - The reverse mix, footprint inputs with centre-pixel labels, penalises both sides for the same
    reason.
- **Gate: FAIL under both fair definitions.** With live-lag weather the model is statistically even with
  persistence. Footprint: −0.009 [−0.030, 0.008]. Centre: +0.002 [−0.013, 0.014]. It is neither
  clearly better nor clearly worse.
- **The model forecasts about 4 times the area that burns.** It predicts 28,770 pixels against 6,721 burned,
  so precision is 15% and recall 65%. Without weather and drought the forecast shrinks to 18,404
  pixels and IoU rises to 0.164, while PR-AUC drops slightly (0.199 vs 0.209). The weather helps rank
  pixels a little, but the 0.621 threshold chosen on the training split is too low for these labels.
  The training labels mark cloudy pixels as uncertain and the FIRMS points can't, which plausibly
  shifts the calibration.
- **The live weather lag costs nothing.** Weather from days t−3 and t−2 scores 0.141, against 0.134 for t−1 and t.
- **Orientation:** identity (south-up) has the best IoU and PR-AUC under both definitions, but the
  margins are small (0.134 vs 0.120–0.132). The DEM match is the decisive evidence; this result is
  consistent with it.
- **Geometry:** degree and km pixels score about the same (0.134 vs 0.129 on 168 tiles), so this test
  can't separate them; the DEM match settled it.
- **Fire source:** adding Aqua or using VIIRS raises persistence more than the model, so Terra is fine.
- **Regions:** almost all the signal is in the West. Central-S and East-S tiles, mostly small burns
  that don't last a day, score close to 0 for both methods.
